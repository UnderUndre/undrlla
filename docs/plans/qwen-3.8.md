# Кастом + Продукт: стратегия "Конвейер кормит автоматизацию"

Короткий ответ: **да, но не "параллельно", а последовательно-вложенно.** Кастом — это не второй проект. Это **сырьё** для продукта.

---

## Почему "просто параллельно" — это ловушка

```
Клиент → "Сделай мне магазин" → 3 недели работы → правки → ещё 2 недели → поддержка → клиент исчез
                                                                              ↓
                                                              Продукт автоматизации стоит на месте
```

Ты продаёшь **часы**. ИИ ускоряет кодинг на 40–60%, но:

- Коммуникация с клиентом (ТЗ, созвоны, "а давайте переделаем") — **не ускоряется**
- Правки и "а я передумал" — **не ускоряются**
- Поддержка после сдачи — **не ускоряется**

Итого: ИИ экономит тебе руки, но не голову и не время на людей.

---

## Правильная схема: каждый кастом = кирпич в продукт

```
┌─────────────────────────────────────────────────────────┐
│  КЛИЕНТ ПЛАТИТ ЗА МАГАЗИН                              │
│                                                         │
│  Ты делаешь магазин НЕ с нуля, а через свой конвейер:  │
│                                                         │
│  1. Шаблон (твой, не чужой)                            │
│  2. Конфиг-файл (JSON/YAML с параметрами клиента)      │
│  3. Скрипт деплоя (одна команда)                       │
│  4. Клиент получает магазин                            │
│  5. Ты получаешь: деньги + улучшенный конвейер         │
└─────────────────────────────────────────────────────────┘
```

**Каждый заказ делает продукт лучше.** Не "я делаю кастом И отдельно пишу продукт". А "кастом — это тест-кейс для продукта".

## Конкретная архитектура конвейера

### Что автоматизируется (продукт)

| Этап | Инструмент | Ручная работа |
| --- | --- | --- |
| Каркас магазина | Medusa 2.0 / Saleor + твой шаблон | 0 |
| Тема/дизайн | 2–3 готовых темы + конфиг цветов/шрифтов | 15 мин настройка |
| Товары | Импорт из CSV/Excel клиента | Клиент сам заполняет |
| Платежи | Stripe/Paddle коннектор | 0 (уже в шаблоне) |
| Деплой | Docker Compose + Traefik + DNS | 5 мин |
| Домен + SSL | Автоматически через Traefik ACME | 0 |
| Лендинг | **Вот тут ручная работа** | 2–5 дней |

### Что остаётся ручным (и это нормально)

- **Лендинг** — ты сам сказал, это ручная работа. Это и есть твоя ценность.
- **Кастомные интеграции** (1С, МойСклад, специфичные CRM) — если клиент просит.
- **Контент** (тексты, фото) — клиентская зона.

## Ценообразование: не продавай "сайт", продавай "запуск"

| Пакет | Что входит | Цена | Твоё время |
| --- | --- | --- | --- |
| **Старт** | Магазин на шаблоне + деплой + 10 товаров | $500–800 | 1–2 дня |
| **Бизнес** | + лендинг + кастомная тема + 50 товаров | $1,500–2,500 | 4–7 дней |
| **Под ключ** | + интеграции + SEO + контент | $3,000–5,000 | 2–3 недели |

**Поддержка:** $50–100/мес (обновления, бэкапы, мелкий фикс). Это твой **recurring revenue** пока продукт не взлетел.

## Где тут Undrlla и автоматизация

Твой продукт автоматизации — это **не отдельный проект**. Это сам конвейер, который ты строишь на каждом заказе:

```
Заказ 1: Делаешь вручную, записываешь скрипты
Заказ 2: Полуавтомат, скрипты уже работают
Заказ 3: Почти автомат, только лендинг руками
Заказ 5: Клиент сам заполняет форму → магазин деплоится автоматически
Заказ 10: Это уже SaaS-продукт
```

**Undrlla/undevops** — это и есть этот конвейер, доведённый до самообслуживания. Не надо строить его отдельно от заказов.

## Поток клиентов: где брать без стабильного inbound

Раз потока нет — не жди его. Иди туда, где **уже есть спрос**:

### Быстрые каналы (первые 2 недели)

1. **Фриланс-площадки** (Upwork, Kwork, FL.ru) — не для "кастомного магазина за $5000", а для "перенести с Tilda на нормальный движок" / "починить WooCommerce". Мелкие задачи → апсейл.

2. **Telegram-чаты** предпринимателей — "Ищу кто сделает магазин". Там каждый день такие запросы.

3. **Партнёрство с маркетологами** — они приводят клиентов на трафик, тебе отдают на "сделай магазин". Комиссия 15–20%.

### Средний канал (1–2 месяца)

1. **Build in Public** — показываешь процесс: "Вот клиент, вот магазин за 2 дня, вот как я это автоматизировал". Это и маркетинг продукта, и привлечение клиентов на кастом.

2. **Ниша** — выбери одну: магазины косметики, магазины электроники, магазины для Турции/Грузии (твоя география из конституции). Ниша = повторяемость = скорость.

## ИИ для кодинга: где реально экономит

| Задача | ИИ помогает? | Экономия |
| --- | --- | --- |
| Написать компонент темы | Да | 50–70% |
| Настроить Medusa модуль | Да | 40–60% |
| Docker/Traefik конфиг | Да | 60% |
| Общаться с клиентом | Нет | 0% |
| Разбирать "а у меня не работает" | Частично | 20% |
| Писать ТЗ по словам клиента | Нет | 0% |
| Деплой и DNS | Да (скрипты) | 80% |

**Вывод:** ИИ экономит на **коде**, но не на **людях**. Поэтому твоя задача — минимизировать коммуникацию через:

- Готовый бриф (форма, не созвон)
- Ограниченный выбор (3 темы, не "нарисуйте мне")
- Чёткие границы ("в стоимость входит X, за Y доплата")

## Главный принцип

> **Не строй продукт в вакууме. Строй его из трупов кастомных заказов.**

Каждый клиент — это тест-кейс. Каждая правка — это баг в конвейере. Каждый деплой — это шаг к автоматизации.

Когда конвейер станет настолько гладким, что ты сможешь сказать "клиент заполняет форму → через час магазин работает" — **вот тогда** это продукт. Не раньше.

А пока — бери заказы, делай быстро, автоматизируй по пути. Это не "параллельно". Это **один и тот же путь**, просто ты на нём зарабатываешь.
